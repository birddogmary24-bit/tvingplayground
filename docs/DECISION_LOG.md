### [2026-03-01] 회원 시스템: localStorage MVP vs 서버 DB
**상태**: 확정
**결정 내용**: 백엔드 없이 localStorage 기반 회원 시스템으로 구현
**배경**: 사용자가 회원별 게임 히스토리 저장과 랭킹판을 요청. 현재 프로젝트에 백엔드가 없음.
**검토한 대안들**:
- 대안 A: Firebase Realtime DB — 실시간 랭킹 가능하지만 설정 복잡도 증가, MVP 단계에 과도
- 대안 B: Supabase — PostgreSQL 기반으로 안정적이지만 외부 의존성 추가
- 대안 C: localStorage — 즉시 구현 가능, 외부 의존성 없음
**최종 선택 이유**: 사용자가 "MVP 개념으로 만들어도 될 것 같아"라고 명시. localStorage로 핵심 기능 검증 후, 필요 시 서버 DB로 마이그레이션.
**영향 범위**: `src/App.jsx` (loadUser/saveUser 헬퍼, generateUser 함수, useEffect 초기화)

### [2026-03-01] 명장면 모드: 주관식 → 객관식(4지선다) 변경
**상태**: 확정
**결정 내용**: 명장면 모드를 주관식(자유입력)에서 객관식(4지선다 A/B/C/D)으로 변경
**배경**: 초기 계획은 주관식이었으나, 사용자가 두 차례 "객관식으로 해줘"를 요청.
**검토한 대안들**:
- 대안 A: 주관식 (자유입력) — 텍스트 매칭/유사도 분석 필요, 오답 판정이 어렵고 사용자 UX 불편
- 대안 B: 객관식 4지선다 — 기존 Quiz 컴포넌트 패턴 재사용 가능, 명확한 정답 판정
**최종 선택 이유**: 사용자 피드백 "주관식은 분석도 어렵고 맞추기도 어려워". 객관식이 UX/구현 모두 간결.
**영향 범위**: `src/App.jsx` (FamousScene 컴포넌트 전체)

### [2026-03-01] 포인트 이중 트래킹 (pt vs totalPt)
**상태**: 확정
**결정 내용**: 사용 가능 포인트(`pt`)와 누적 포인트(`totalPt`)를 분리 관리
**배경**: 포인트로 유료 VOD를 구매할 수 있는 기존 기능이 있는데, 구매 후 레벨/랭킹이 하락하면 UX가 나빠짐.
**검토한 대안들**:
- 대안 A: 단일 포인트 — 구매 시 레벨/랭킹 하락 위험
- 대안 B: 이중 트래킹 — 구매는 `pt`에서만 차감, `totalPt`는 보상으로만 증가 → 레벨/랭킹 절대 하락 안함
**최종 선택 이유**: 게임 보상 의욕을 유지하면서 포인트 소비 기능도 살리려면 이중 트래킹이 필수.
**영향 범위**: `src/App.jsx` (rew 함수, getLevel, getLvProgress, 랭킹 정렬)

### [2026-03-01] 랭킹 보드: 가짜 유저 15명 혼합
**상태**: 확정
**결정 내용**: 코드 내 상수로 가짜 유저 15명을 정의하고 실제 유저와 혼합 정렬
**배경**: localStorage 기반이므로 다중 유저 데이터가 없음. 랭킹판이 1명만 있으면 의미 없음.
**검토한 대안들**:
- 대안 A: 실제 유저만 표시 — 항상 1명, 랭킹 의미 없음
- 대안 B: 가짜 유저 혼합 — 경쟁 심리 자극, 레벨업 동기 부여
**최종 선택 이유**: MVP에서 즉시 "랭킹 경쟁" 경험을 제공. 가짜 유저 포인트를 30~1850 범위로 분산하여 실제 유저가 게임 플레이를 통해 순위 상승을 체감할 수 있도록 설계.
**영향 범위**: `src/App.jsx` (FAKE_USERS 상수, MY 탭 랭킹 섹션)

### [2026-03-01] 게임 이미지: TVING CDN URL 직접 사용
**상태**: 확정
**결정 내용**: `shows.js`에 이미 수집된 TVING CDN 이미지 URL을 명장면 모드 문제 이미지로 활용
**배경**: 이전에 이미지 소싱이 최대 과제였으나, shows.js에 실제 TVING 클립 썸네일/배너/포스터 URL이 수집되어 있음.
**검토한 대안들**:
- 대안 A: 웹 검색으로 새 이미지 수집 — 불안정, 저작권 문제
- 대안 B: TMDB API — 추가 의존성, 한국 콘텐츠 커버리지 불확실
- 대안 C: shows.js 기존 URL 활용 — 이미 수집 완료, 안정적, ShowImage 폴백 지원
**최종 선택 이유**: 추가 작업 없이 즉시 사용 가능. ShowImage 컴포넌트의 SVG 폴백이 깨진 이미지도 처리.
**영향 범위**: `src/App.jsx` (FamousScene allQ 배열의 img 필드)
